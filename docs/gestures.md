# 飞字与翻页：手势与动画

两块手势 —— 候选行的**上滑选字（飞字）**和**横滑翻页** —— 共用同一份数学（`ui/DragGesture.kt`）。
三处手势（飞字、候选行翻页、L5 行翻页）只差**阈值取值**与**轴向**，松手后的惯性由
`ui/Fling.kt` 统一处理。

## 一条硬规矩：绘制用位移，判定用进度

这是 2026-09-30 真机报「翻页不跟手」「翻页动画太短」后立的规矩，两种量不能混：

| 量 | 含义 | 用途 |
| --- | --- | --- |
| `slide(travel, …)` | **像素**。画面该跟着手指挪多少 | **只给绘制用** |
| `progress(travel, threshold)` | `0..1`。离提交线还有多远 | **只给判定用** |

跟手的定义就是**画面位移 = 手指位移**，中间不做任何归一化。此前绘制用「进度 × 行宽」，
而提交线只有行宽的 0.22，于是：手指走 0.22、画走满整行（放大 4.5 倍）；前一段全在死区里
画面零变化；拖过阈值后画面干等，松手时 `from == target` 直接零动画 —— 三个症状一个根因。

死区内仍给响应（`DEAD_SLIP = 0.33`，按比例打折），消掉「手指在动、屏幕不动」那段静默。

## 进度模型

```
p = (位移 − 死区) / (阈值 − 死区)
```

- 位移 ≤ 死区 → `p = 0`：抖动不启动
- 死区 → 阈值 → `p` 从 0 涨到 1，与手指 1:1
- `p = 1` 即触发线：翻页类松手提交，飞字类越过即由动画接管
- 松手时 `p < 1` → 反向动画退回 0（回退是动画，不是瞬移）

**死区是固定常量 `DEAD_DP = 8dp`**，横滑与上滑共用，**不随触发阈值变化**（`DEAD_FRAC` 与
`dead(threshold)` 已删除；`progress`/`slide` 的 `dead` 是必填参数，类型上不给「按比例算」留后路）。

| 手势 | 提交线 | 位移上限 | 轴 |
| --- | --- | --- | --- |
| 飞字（上滑选字） | 设置项 100/160/240px，默认 160（旧偏好有迁移） | — | 纵向 |
| 候选行翻页 | 行宽的 `PAGE_COMMIT_FRAC`（默认档 0.22） | 整行宽 | 横向 |
| L5 行翻页 | 同候选行（`L5_COMMIT_FRAC`） | 整行宽 | 横向 |
| **键盘表面横滑** | **死区之外 4 / 8 / 20px（默认 8）** | — | 横向 |

键盘表面那一档的口径是**「死区之外还要走多远」，不是手指总行程**。基线定在死区被跨过的
那一帧，死区已经走完了，所以提交线直接拿来比。这样有两个好处：

1. 每个比较点不必各自记得减一次死区 —— 旧口径下候选栏减了、`FlyDetector` 的抬手兜底忘了减，
   两处量纲对不上，表现为「跟手有了、翻页触发不了」；
2. **改死区不再暗中改灵敏度**：三档的台阶不会被死区压扁，才真正加得出「更灵敏」那一档。

## 动画：官方物理引擎（`androidx.dynamicanimation`）

积分、打断保速、变 dt 稳定全部交给官方 `SpringAnimation`，由 `SpringChannel` 驱动
（2026-10-02 用户「使用物理引擎重构手势和动画」「不要自己实现物理引擎和动画库」）。

```
k = m·ω₀²        ω₀ = 2π/response        c = 2ζ·√(km)
```

- 参数用 **(response 秒, 阻尼比 ζ)** 而非 `(k, c)`：后者的量纲要人脑换算，调不出「多久到」。
- **默认一律 ζ ≥ 1**（不过冲）——翻页/橡皮筋/键帽回弹读起来都像 bug。
- **时长不再给定**，由行程与初速算出来。

已迁移：候选行翻页、橡皮筋弹回、L5 横滑、L4/L5 键帽进退场。
未迁移（仍是固定时长 + `Fling.DECELERATE`）：飞字起飞、候选词替换。

## 惯性：匀减速 + 摩擦

松手时**落到哪**由 `Landing` 定，**怎么过去**由弹簧积分：

```
v(t) = v₀ − a·t          t_stop = v₀/a          s_stop = v₀²/(2a)
a = DECEL = 12000 px/s²  ≈ "快速划过一行约 250ms 停"
```

落点永远夹在起终点之间：惯性再大也只把这一页补完，不连翻两页。

## 惯性：匀减速 + 摩擦

松手时**落到哪**由 `Landing` 定（匀减速 + 库仑摩擦），**怎么过去**由弹簧积分：

```
v(t) = v₀ − a·t          t_stop = v₀/a          s_stop = v₀²/(2a)
a = DECEL = 12000 px/s²  ≈ "快速划过一行约 250ms 停"
```

落点永远夹在起终点之间：惯性再大也只把这一页补完，不连翻两页。

**为什么手写这个曲线而不用 `DecelerateInterpolator`**：单测实测默认构造器返回的是恒等函数
（factor=1 等价线性）。物理模型是权威，插值器必须服从它，所以曲线直接写成 `2p − p²`
并由 `GesturePhysicsTest` 钉住与模型一致。

**速度只看最近两点**（`SpeedTracker`），不做窗口平均：实际手势常出现「快甩一段 → 手指停住 →
再抬手」，按窗口平均会把整段的快速度带进来，判成快甩，于是松手瞬间页面又自己滑出去半屏 ——
正是「手已经停了它还在动」的怪异感。两个最小判据挡噪声：位移 < 2px 视为已停、
时间差 < 8ms 不给速度。

**惯性落点 `projectLanding`** 有两个约束：

1. 速度方向必须朝着目标，否则不算惯性（往回甩时速度符号相反）；
2. **落点不越过目标** —— 再大的甩也只补完这一页，不连翻两页。连翻要靠两次手势各翻一页，
   单次手势翻两页会让用户失去「翻到哪了」的把握。

**提交判定是两个条件的或**：手指位移过提交线，**或**惯性落点在过线一侧（甩过去）。
轻推要拖到位才翻，快甩不用 —— 这是真实物理。

## 触发优先级与接管

`ACTION_MOVE` 里一次移动只可能有一条拖动在跑：

1. **翻页先判**（横向占优）：那一侧有页 → 跟手翻页；**没有页 → 橡皮筋拉伸**（见下）
2. **上滑次判**（纵向占优）→ 飞字
3. 都不接管：若飞字正在拖，取消它

## 越界橡皮筋（拉伸变形）

首/末页往回拖时没有相邻页。此前是**整条拖动都不接管**，手指在动、屏幕纹丝不动 ——
那不是「到头了」的反馈，是「卡了」。

`Rubber.shift(raw, scale, limit) = raw / (1 + raw/scale)`，渐近于 `scale`，所以：

- 越拉越沉（相邻等长位移，拉得越远得到的画面位移越小）
- 拉多远都不会飞出区域 —— 用渐近线而不是「固定折扣」，固定折扣下拉很远会把键整个拉出屏幕，
  而用户明确要求「动画完全在自己区域内」

绘制是**围绕行中心横向压缩** + 沿越界方向平移一点（压缩量封顶 8%）。围绕中心而不是推向一侧，
后者看着像「内容没对齐」。松手弹回，时长同样由松手速度决定。

## 飞字的两段

`flyP` 一根数轴两段：

- **拖动段 `[0,1]`** —— 跟手指。词上移 `0 → 26dp`，其余候选渐隐到 `0.4`。
- **完成段 `(1,2]`** —— 越过阈值后动画接管，飞到 `64dp` 并淡出。

```
others = 1 − 0.6×drag        // 拖动段
others = 0.4×(1 − s)         // 完成段
lift   = 26dp + 38dp×s
```

快进慢停由 `Fling.DECELERATE` 这个**时间**维度的插值器负责，`s` 当线性比例用。此前在绘制里
手乘 `s²` 造曲线，那是把时间曲线混进空间计算：时长、抬升、淡出三处各乘一遍，改一个牵动三个。

## 震动反馈

四个确认点，全部收口在 `ime/Haptics.kt`（一个总开关，设置 → 常规 → 震动反馈）：

| 位置 | 强度 | 时机 |
| --- | --- | --- |
| 飞字过阈值 | 确认（12ms） | 首次越过的那一下，拖动中不震 |
| 翻页提交 | 确认（12ms） | 提交的那一刻 |
| Caps 锁定/解锁 | 锁定（14ms） | 锁定态有↔无的变化 |
| 层锁定/解锁 | 锁定（14ms） | 同上（Alt/Sym） |
| 越界到头 | 确认（12ms） | 橡皮筋松手 |

三条原则：只在状态真变了时震；短促一下（不是持续嗡）；可关。锁定类比确认类重一点 ——
「锁住了」比「过了」更需要实感。单击借一层**不震**（打字过程中的常态，震了像误触）。

状态机不依赖 `Haptics`，测试传 null 即可。

## 抬手与打断

`ACTION_UP`：

- 橡皮筋中 → 弹回，不翻页
- 飞字中 → 松手前按最终 dy 再结算一次，`flyP >= 1` 就起飞上屏，否则淡回
- 翻页拖动中 → 过线提交 / 没过线收回
- 反向动画还在播（`pageFrom` 非空）→ 本次抬手**不重复判定**
- 都没拖 → 位移小于 `touchSlop` 算点按；否则走快速上滑（`flingDistance = 24dp`）或
  **横向快扫翻页**（候选词上滑动也能翻页，用户 2026-09-30 要的）

`ACTION_CANCEL`（系统打断）当作松手，不留半途状态；橡皮筋直接弹回，不给震动（不是主动确认）。

## 长按删除的互斥

`ACTION_DOWN` 挂 600ms 长按定时器。`ACTION_MOVE` 里只要移出按下槽位或位移超过 `touchSlop`
（任一轴），立刻撤掉 —— 上滑拖动中绝不能误触发长按删除。

槽宽恒为 `width / 5`，与 Titan 2 物理键盘的 10 列对齐（槽宽 = 2 个键列）。

## L4/L5 键序动画

键序变化时走**从右侧移入**的进入动画（`L4PanelView.runEnterAnimation`）：

- 位移 = `min(视口宽, 键组自然宽)` ⇒ **动画完全在本区域内**，不越界影响外层
- 非线性缓动（`Fling.DECELERATE`），300ms
- **键的身份取输出**（`KeyIdentity`），不是标签：全角 `；` 与半角 `;` 是同一把键，
  身份还在就原地不动、只换内容，不该「消失一把再补一把」
- 只有真正新增的键才从右侧进来；身份还在的键位移为 0

## 渲染合并

`RenderPump`（`Channel(CONFLATED)` + yield + drain）把一次按键里的多次 `render()` 合成一次重绘。
按键入口不 Flow 化（`onKeyDown` 必须同步返回消费判定）。

拖动与动画过程中**不走 RenderPump** —— 手势跟手必须实时，合并渲染在这里是负担。

## 已知限制

- 手感没法在自动化测试里验：`tools/aitest` 的注入走屏幕坐标系模拟，与真手指的 TOUCHPAD 路径
  等价但力度感不同。**这一轮所有手感改动都需要真机确认**。
- 拖动段抬升 26dp / 完成段 64dp / 渐隐到 0.4 / 翻页 0.22 行宽 —— 这些是手感值，改之前先在真机上试。
- 橡皮筋封顶 56dp、形变 8% —— 同上。
