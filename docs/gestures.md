# 飞字与翻页：手势与动画

两块手势 —— 候选行的**上滑选字（飞字）**和**横滑翻页** —— 共用同一份数学，见 `ui/DragGesture.kt`（纯函数，可 JVM 单测）。三处手势（飞字、候选行翻页、L5 行翻页）只差**阈值取值**与**轴向**。

## 共用的进度模型

```
p = (位移 − 死区) / (阈值 − 死区)
```

- 位移 ≤ 死区 → `p = 0`：抖动不启动，视觉零变化
- 死区 → 阈值 → `p` 从 0 线性涨到 1，**与手指 1:1**，这就是"跟手"
- `p = 1` 即触发线：翻页类松手即提交并补完剩余动画，飞字类越过即由动画接管飞走
- 松手时 `p < 1` → 反向动画退回 0（回退是动画，不是瞬移）

死区一律取阈值的 **1/4**（`DEAD_FRAC`），三处不再各拍一个数。

跟手动画的基准时长 `SETTLE_MS = 260ms`，实际时长按剩余距离等比缩放并夹在 `[60, 260]`。所以"半路松手"和"一次划到底"速度一致 —— 这是跟手手感的关键：**动画速度不随松手早晚跳变**。

| 手势 | 阈值 | 死区（1/4） | 轴 |
| --- | --- | --- | --- |
| 飞字（上滑选字） | 用户设置，默认 160px（`flyThresholdPx`，旧偏好有迁移） | ≈40px | 纵向（上为正） |
| 候选行翻页 | 行宽的 1/3（`PAGE_COMMIT_FRAC = 0.33`） | 行宽 ≈ 1/12 | 横向 |
| L5 行翻页 | 同候选行 | | 横向 |

## 触发优先级与接管

`CandidateBarView.onTouchEvent` 的 `ACTION_MOVE` 里，一次移动只可能有一条拖动在跑：

1. **翻页先判**：`adx > 死区 && adx > ady`（横向占优）且那一侧真的有页 → `beginPageDrag` 接管。如果此时有正在上滑的词（`flyP >= 0f`），先 `cancelFlyDrag()` 把词放回去，**别两条拖动同时跑**。
   首/末页往回拖不接管（那一侧没有页），留着给点按/上滑。
2. **上滑次判**：`dy > 死区 && dy > adx`（纵向占优）→ `beginFlyDrag` + `setFlyDrag` 实时驱动。
3. **谁都不接管**：若飞字正在拖（`flyP >= 0f` 且没在播动画），取消它 —— 拖回来/拖歪了就松手放弃。

横滑接管用 `adx > ady` 而不是各轴独立阈值，所以斜着划时轴向优势决定谁赢，不会在边界反复横跳。

## 飞字的两段

`flyP` 是唯一的进度变量，分两段用：

- **拖动段 `[0, 1]`** —— 跟手指。词上移 `0 → 26dp`，同时其余候选渐隐到 `0.4`。
  绘制（`drawFly`）：
  ```
  others = 1 − 0.6 × drag        // 拖动段：其余候选线性渐隐到 0.4
  lift   = drag × 26dp           // 词缓慢上移
  ```
- **完成段 `(1, 2]`** —— 越过阈值后动画接管，从当前 `flyP`（没拖过就从 0）继续飞到 2。
  ```
  others = 0.4 × (1 − s²)         // 二次曲线淡完，比线性更快收
  lift   = 26dp + 38dp × s²      // 加速飞到 64dp 并淡出
  ```
  用 `s²` 是因为"飞出屏幕"要有加速度感，线性会显得被拽着走。

词飞出后由调用方（`onSelect`）选字上屏。`startFlyAnim` 一进来就把拖动状态抓成局部变量再 `cancel()` —— 否则 `resetFly` 会先把要用的值清掉。

**分区内重入**：拖回来又拖上去时重新接管（`beginFlyDrag` 自带防重入：同 zone 且没在播动画就直接返回）。

## 翻页的绘制

稳态直接画 `slots`。翻页过渡期（`pageFrom` / `pageTo` 非空且 `pageU > 0`）画两页：

```
slide = pageDir × pageU × width   // 旧页位移：顺方向拖多远就移多远（跟手）
旧页：translate(−slide)            alpha = (1 − u)
新页：translate(−slide + dir×width) alpha = u
```

等宽等距的槽宽 ⇒ 中线恒过中心键心（奇数把）或中缝（偶数把），左右边距对称。

进度换算 `pageDragProgress(x, baseX, dir, viewW)`：`dir = +1`（下一页）时手指**向左**移才推进，`dir = -1` 反之。所以**反向滑动自动把进度拉回 0**，松手就是"收回原页" —— 不需要额外判"划回去"。

## 抬手与打断

`ACTION_UP`：

- 飞字中 → 松手前再按最终 dy 结算一次（手指可能在最后一段没产生 MOVE），`flyP >= 1` 就 `startFlyAnim` + `onSelect`，否则 `cancelFlyDrag`。
- 翻页拖动中 → `endPageDrag` 同一套判定（过线提交 / 没过线收回）。
- 接管后的反向动画还在播（`pageFrom` 非空）→ 本次抬手**不重复判定**。
- 都没拖 → 位移小于 `touchSlop` 算点按（两端窄条是翻页箭头，中间按槽位选字）；否则走"快速上滑"老路径（`flingDistance = 24dp`）。

`ACTION_CANCEL`（系统打断）当作松手处理，走同一套判定，不留半途状态。

## 长按删除的互斥

`ACTION_DOWN` 挂 600ms 长按定时器。`ACTION_MOVE` 里只要**移出按下槽位**或**位移超过 `touchSlop`（任一轴）**，立刻撤掉定时器 —— 上滑拖动中绝不能误触发长按删除。

槽位判定 `cellIndexAt`：两侧翻页箭头占的窄条只挡点按和上滑起手入口，**不移动分区边界**。槽宽恒为 `width / 5`，与 Titan 2 物理键盘的 10 列对齐（槽宽 = 2 个键列）。

## 渲染合并

`RenderPump`（`Channel(CONFLATED)` + yield + drain）把一次按键里的多次 `render()` 合成一次重绘。按键入口不 Flow 化（`onKeyDown` 必须同步返回消费判定），输出侧不整体流化（写入必须同步）。

拖动过程中动画每帧 `invalidate()`，**不走 RenderPump** —— 手势跟手必须实时，合并渲染在这里是负担。

## 已知取舍

- 飞字的"手感"没法在自动化测试里验：`tools/aitest` 的注入走屏幕坐标系模拟，与真手指的 TOUCHPAD 路径等价但力度感不同，手感仍需人工确认。
- `flyThresholdPx` 默认 160px 是历史值（设置项从旧档位迁移过来）。判断标准是"拇指上滑一个自然行程"，比行宽的一半略大。
- 拖动段抬升 26dp / 完成段 64dp、其余候选渐隐到 0.4、翻页 1/3 行宽 —— 这几个数是手感值，代码里没有注释解释为什么是这些，改之前先在真机上试。
