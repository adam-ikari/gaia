Titan 2 的屏宽**三个数同时成立**,各自回答不同的问题(2026-09-30 用户澄清「576 和 598 都是对的」):

| 量 | 值 | 是什么 | 谁在用 |
| --- | --- | --- | --- |
| 物理面板 | 1440 × 1440 | 物理像素 | 候选行通栏宽 = **1440px**、截图/录屏尺寸 |
| 原生逻辑宽度 | **576dp** | 面板固有的 dp 宽(1440 ÷ 原生 density 2.5) | 站点响应式断点(浏览器 CSS px 这条线) |
| 改后的最小逻辑宽度 | **598dp** | **用户在开发者选项里改过的**当前值 | 代码注释里的屏宽、布局算例 |

**不再有"哪个才对"的问题 —— 是三个不同的量。** 我前两轮来回改(576 → 598 → 又想统一)是在
错误的框架里找唯一解:拿物理 px 反推 dp,然后纠结推出来的数对不对。正确的问法是
**"这个数是哪一类"**。

**写注释的规矩(踩了两次才总结出来)**:

- 屏宽类注释 → 写 **598dp**,并注明"用户改过的最小逻辑宽度"(代码里原本就是这个数,是对的);
- dp→px 的换算 → **不写死 density**。原生是 2.5,用户改过逻辑宽度后约 2.41,取决于当时设置;
- 像素尺寸(候选行宽、截图尺寸、录屏分辨率)→ 直接写 **1440**,那是物理值,不受设置影响;
- 站点 CSS 断点 → 按 **576**,但要意识到它对应的是**浏览器**那条线,不是 Android dp。

**通用教训(比这次的具体数字更值得记)**:同一台设备的"物理尺寸 / 原生逻辑尺寸 / 用户改过的
逻辑尺寸"是三个量,换算关系是 `dp = px / density`,而 **density 本身是设置项的函数**。
任何"从 px 推 dp"然后怀疑 dp 错的推理都是错的 —— dp 根本不由 px 单独决定。
