# 策略注册表与 L4 上下文键位

## 结论

### 三轴与合成

- **语言与输入法是策略**:`Language`(id/chipLabel/methodId/showShiftChip/shiftTapsEnabled/l4Extras/l4Replace|l4Drop|coreKeys/mapText/onEnter/composes/commitText)、`InputMethod`(query/onCommitted/removeUserWord/userCount)由 `ImeRegistry` 注册;`ImeState.languageId: String` 取代 `ImeMode.CN/EN` 枚举。**加语言/加输入法只注册不改核心状态机** `ImeController`,UI `ImeService` 一律按 id 查策略,`ImeRegistryTest` 即回归证明。
- `FieldKind.from(EditorInfo.inputType)` → TEXT / URL(`TYPE_TEXT_VARIATION_URI`)/ EMAIL / 数字类六种(number / signed / decimal / signeddecimal / phone / datetime)。

### L4/L5 就是一条优先级列表(2026-09-30 用户定案,现行)

**「L4L5 显示的按键是有优先级的」**。优先级**不是显示上的花活,而是"这把键留在 L4 还是被推进 L5"的判据**——因为两行的切分是**前缀切**(`L4PanelView.onMeasure` 取"装得下的最长前缀",按*前缀最长标签自然宽*判装得下,装不下的尾巴整段进 L5)。

优先级由**每把键自己带**(`L4Key.priority`,默认 `L4Priority.PHRASE`)。`ImeRegistry.l4Keys` 只做两件事:**同名同输出撞车时留优先级高的那把** + **按优先级稳定排序**(同级保持来源给定的先后——键位套里"按常用度排好"的次序不能被打乱)。优先级**不进键位文件格式**(`label=output` 照旧):文件排不出"哪一把更该留 L4",那是输入法自己的判断。

| 档 | 值 | 内容 |
|---|---|---|
| `FIXED` **固定键** | 0 | **L1-L3 敲不出、必须固定显示**的键:① 出厂核心 ASCII 标点 `；` `$`(`KeyLayout.L4_CORE`);② 语言补差键里的**通用高频标点** `…` `——` `、`(半角态 `...` `--`) |
| `PHRASE` **模式组合短语** | 10 | **每个输入模式的组合短语**:键位套 `[L4 url\|email\|number\|…]` 的出厂预置与用户自定义(`http://` `.com` `+86`…)。也是键位文件 `[L4]` 段能写出来的全部内容的默认档 |
| `COLD` **冷门符号** | 20 | `「」『』〔〕※`:同属 L1-L3 敲不出的键,但很少用 ⇒ 排最末、行紧时**先**溢出(网址模式要把位置让给 `http://`) |
| `USER` **用户自己编辑录入的短语** | 30 | **还没实现**:键位编辑器目前只写得出"这一把键是什么",没有"按输入框分类 + 长期累积用户常敲短语"这套数据源。档位先占住,接上时排在 `PHRASE` 之后即可,不动已有三档 |

**顺序定案沿革**(三次,每次推翻前一次):

1. 2026-09-28「这类由输入法注册的 L4 虚拟按键应该显示在最左侧」= 语言补差键排最左;
2. 2026-09-29「固定核心键排最前、语言补差键排最后」= 靠 `core + rest + extras` 的**拼接顺序**副产物——顺序对但没有约束力,谁改拼接顺序就静默破掉;
3. **2026-09-30 现行**:由 `L4Priority` 显式承担。触发原因是用户报障「**在拼音输入法邮箱模式 `...` 和 `--` 就显示到 L5 的末尾了,我希望显示在 L4 的开头**」——补差键整组排在词组之后造成的。现在高频那批与核心键同属 `FIXED` 档。

**配套规则**:

- **撞车留高的**:`KeyLayout.l4Combined`(默认套 = 核心键 + `[L4]` 自定义)与 `ImeRegistry.l4Keys`(核心键 ∪ 键位套 ∪ 补差键)两处一致——同一把键只留一把,**优先级高的赢**。
- **换整把键必须带过优先级**:`Language.coreKeys` 钩子换键帽/输出时,新构造的 `L4Key` 要传 `it.priority`,否则退回默认 `PHRASE` 档,固定键被降到词组那档去。

### 固定键按输入框的合法值过滤(两把尺)

固定键"必须显示"的前提是**它在这个输入框里合法**。合法性有两层,两把尺都要用上:

- **`FieldProfile.l4CoreKeys`**:圈定**出厂核心键**的合法子集——URL 全留(`;` `$` 都是 RFC 3986 sub-delim)、邮箱只留 `$`(`;` `\` 不在 RFC 5322 atext)、数字类 `emptyList()`(全非法)。
- **`FieldProfile.l4AsciiOnly`**(2026-09-30 加):**整个 L4 键集只收 ASCII**,给邮箱。依据:邮箱地址是纯 ASCII(RFC 5321/5322——local part 只有 atext `A-Za-z0-9 !#$%&'*+-/=?^_\`{|}~`,引号形式供应商基本不收;domain 只有字母/数字/`-`/`.`,IDN 走 punycode)。**补差键是中文标点、键位套也可能被用户写进中文**,它们同样要过这一关,否则会在邮箱框里摆一排发不出去的中文标点。
  - 邮箱框因此**默认英文态**、且全角态的 `…` `——` `、` `「」` 整个退场;半角写法 `...` `--`(字符本身 `.` `-` 合法)照常显示并排在 L4 开头。
  - **网址框相反,不做这个过滤**:中文路径/查询在实际使用里很常见(浏览器会 percent-编码),RFC 3986 的纯 ASCII 限制在浏览器场景不成立。
- 数字类的补差键另有 `digitsOnly` 一刀全退场(数字框里摆一把省略号是荒谬的)。

### 显示前的筛与重建

- **必过 producible 筛**(2026-09-29 定案,推翻 2026-09-28"不做程序筛选"):放在 `ImeRegistry.l4Keys` 里**合成与排序之后**。取**当前语言 + 当前全角开关**下 L1/L2/L3 真正敲得出的并集(`lang.layerMap` 优先,否则键位表出厂值),L4 键的输出命中它就不显示。筛必须**运行时**:编译期把内容写死会失去不同机型的适配能力(键位表随机型不同,某层没有某键 ⇒ L4 自动少一把、多一把)——用户明确否掉"编译时过滤器 + 固定内容"。
- **签名重建**:`ImeController.l4Signature()` = **最终键序(逐把 标签+输出)的内容 hash**(2026-09-29 定案,取代"键位套id|语言id"那种要靠人记得列全来源的签名,漏一个就"键换了却不重绘")。**优先级/合法值变化必然改顺序 ⇒ 也改签名**,不会出现"顺序变了却不重绘"。

### 数字类(digitsOnly)

- 聚焦即**锁 L2 数字层**(免按 Alt);Alt 芯片 = `0-9` + 该类型合法单字符(如实标注可输字符集);物理白名单 = `0-9` + `FieldProfile.digitChars`,**加上 L4 当前显示的键的输出**(多字符组合一并放行)。
- **L4 放短语组合**(2026-09-29 定案,`+86` 这类):合法单字符 `- . / : + * #` 全在 L2,按 producible 那把尺会被整段筛空——**"出厂为空"是结果不是要求**:物理键一次只出一个单字符,多字符组合天然 L1-L3 按不出,所以数字套必须放组合键。**出厂只有电话类型有键**(`+86 +1 +81 +44` 国际区号,用户原话"只有电话输入时候需要+86等按键 其他的没有"),其余五个数字类型出厂为空(合法字符全在 L2、没有组合可放),可在 `[L4 datetime]` 等段自写。

### 版式

- **L4 中区**:不滚动、键一把不裁;**等宽槽**版式(间距 4dp、左右边距对称 6dp、槽宽 `W = min(填充值, 72dp 封顶)`),填充值→两端对齐、封顶→整组居中,中线恒过键心或中缝;每键最小宽 36dp;分页按"前缀最长标签宽"判装得下。
- **L5 行**(状态栏上方、齿轮左侧键盘图标切显隐):只装 L4 装不下的溢出尾巴 + 横滑翻页,**与 L4 同一套等宽槽、同样居中**(2026-09-29 定案,先后推翻"左对齐 + 自然宽"与"贴行底")。**L5 无溢出时 GONE、组词态整行让位**;L5 出现会改 `contentTopInsets`,切换后要通知窗口重算并**补一次延迟重排**。
- **输入条背景纯黑**(2026-09-29):`ImeTheme.DEFAULT.barBg` 全改 `#000000`(其余 6 套主题色板不动,主题选择器仍有效)。
- **验证载体**:实验场 `PlaygroundActivity` 有 L1-L5 键位总览 + URL/数字两个上下文输入框,五种输入框逐一真机核对。

## 依据

- 2026-09-28 需求三条:L4 可变(网址框 `http://` 等)、输入数字时 alt 状态显示为变种 0-9、拼音输入时 L4 增加分节符。
- 2026-09-28 用户原话:"根据输入框的输入类型决定";"L4上需要固定显示\,因为前三层没有";"不要在网址输入模式时在L4显示/这个按键是L2的";"这类由输入法注册的L4虚拟按键应该显示在最左侧";"不需要程序里筛选 L1-L4都是固定的按键"(**已于 2026-09-29 被推翻**)。
- 2026-09-29 整条重理 L4/L5 显示规则,用户原话:"L4不要显示L1-L3已有的按键";"白名单的内容也是L1-L3按不出的键或者短语组";"数字态默认键位下 L4 为空是不对的 这是一个结果不是一个要求";"编译时过滤器不考虑 这样失去了不同手机的适配能力"。
- 2026-09-29 固定核心键补 `\`,**2026-09-29 又从固定键里删掉**(L3 `Sym+z` 就能敲出它,按"L1-L3 已有的不进 L4"这把尺它不该占中区,L2 严格按 Titan 丝印、丝印上也没有它)。组合键 `-> != ==` 已按用户要求移除。
- 2026-09-30 优先级模型三轮定案,用户原话:"加入一条规则 L4的固定按键优先级最高 不要被模式扩展的词组推到L5";"不对 在拼音输入法邮箱模式...和--就显示到L5的末尾了,我希望显示在L4的开头";"hot这个机制不对 L4L5显示的按键是有优先级的";"比如L1-L3无法输入的ascii字符是固定需要显示的(但是需要根据输入框的合法值过滤)这个优先级最高,然后是每个输入模式的组合短语,然后是用户自己编辑登录的短语(还没实现)"。
- 2026-09-30 用户追问「**邮箱模式 中文是合法的吗**」⇒ 不合法(RFC 5321/5322,邮箱地址纯 ASCII),补 `FieldProfile.l4AsciiOnly`。此前「合法的留、非法的去」只落在核心键上,补差键(中文标点)漏网——**这条追问等于给"合法值过滤"补上了它缺的那一半**。
